# Character, Inventory and Adventure start — isolated review candidate

## Scope and authority

This branch starts from accepted main `4d4de0b0cc16ff21f84c24b63df7cbd5290f81df`. It changes protagonist creation and player-facing presentation without taking over a campaign, submitting a turn, dispatching media, or changing the owner's database. Migration 42 is a candidate and has been tested only in disposable databases. It must precede use of the new creation path; the existing Greenmarch campaign and older saves continue to use the legacy Character fallback.

## What changed

- New protagonist proposals include a bounded, owner-reviewed public character sheet. Fantasy-style proposals can include six attributes, skills, abilities, limitations and a proposed combat profile. Worlds without conventional RPG anatomy or combat use a narrative sheet. The review visibly separates established public capabilities from descriptive sheet suggestions and lets the owner correct the sheet style; switching to RPG style starts with bounded placeholder scores and requires a separate combat-profile approval. These descriptors do not grant powers or roll modifiers. Numeric HP, attack, defense, skill, and a grounded starting weapon only become gameplay authority through the existing bootstrap approval transaction.
- Additive migration `202610060042_character_sheet_bootstrap.sql` stores the approved sheet on the public Entity, preserves old rows and old save manifests as `null`, and adds the field to the established source projection. No ordinary gameplay patch may write it. No new table, provider, or Character Model authority was added.
- The live Game, Character and Inventory presentations now reuse the actual Phase-0 DOM classes and composition from `game.tsx`, `character.tsx`, `inventory.tsx`, `shell.tsx` and `globals.css`. Thin public view models supply live scene, controlled hero, present companions, recorded stats, equipment, carried inventory and accepted art. Phase-0 fixture values and artwork never enter the live campaign. Game retains the cinematic scene/story, composer and compact context rail. Character restores the three-column stats / portrait-equipment / inventory grid; the phone layout stacks these sections without clipping.
- Reviewed sheets retain established public World capabilities and limitations alongside descriptive sheet entries, while Level follows the current authoritative Entity stat. Existing Greenmarch-style heroes without a reviewed sheet receive a read-only presentation of public Entity values and only protagonist capabilities present in both the current Actor and the exact owner-approved creation review; the full original biography remains available in Background. The fallback does not invent numeric attributes. No unaccepted draft art appears as ordinary portrait or item art; accepted standalone Assets are usable before a separate visual-reference approval. The no-art stage is neutral, and narrative-mode heroes use an abstract fallback rather than implied human anatomy.
- Inventory distinguishes equipped gear and possessions, keeps the Equipment section visible even when empty, supports category scanning, and leaves exact record editing under a collapsed owner section. Character's right grid shows only recorded carried/equipped items, not hero-owned items in a remote stash. Trade is contextual. Party shows companions, while ordinary NPCs remain in Journal → People. Journal defaults to a compact Current Adventure with expandable full public text; management and history remain under Advanced. The first-adventure review leads with the playable proposal and keeps corrections secondary.
- A current known Location with no saved map layout appears at the center of a provisional atlas view. This presentation never changes travel or gameplay Location. Map illustration preparation uses the existing map media lifecycle and first establishes the provisional presentation placement through the existing map-layout authority, without requiring manual layout work.
- FRAME and subject-image controls show compact saved, pending, draft, and recovery states. Retry uses the same request identity. Media failure does not block play or make a new paid request automatically.
