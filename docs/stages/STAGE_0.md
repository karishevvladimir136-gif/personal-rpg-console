# Этап 0 — подготовка и исходный замер

Прочитай `CLAUDE.md` и `docs/REBUILD_PLAN.md`. Этот этап не меняет игровой код и не трогает базу владельца.
Платные запросы к моделям в этом этапе запрещены.

## 1. Ветка и окружение

1. `git fetch origin`, создай ветку `claude/rebuild-base` от коммита `65dc99c105d86b2860d284d10846c450d20b3e2d`
   (ветка `codex/astra-fictional-world-freedom`), затем ветку этапа `claude/stage-0-baseline` от неё.
2. `pnpm install`, затем `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`.
   Запиши реальные результаты (сколько тестов прошло/упало/пропущено, время). Ничего не чини — только зафиксируй.
   Если что-то не запускается из-за окружения Windows, опиши, что именно и почему.

   `RPG_DESIGN_DOCTRINE.md`, `LIVING_CHARACTERS_BRIEF.md`, `COGNITIVE_DM_CRAFT_RESEARCH.md`,
   `POSITIVE_AFTERGLOW_BRIEF.md`, `LOCAL_OWNER_STARTUP.md`, `SUPABASE_SETUP.md`, `START_HERE.md`,

## 3. Стенд оценки

Цель: одной командой прогонять сценарии игры через настоящий путь хода на одноразовой базе и получать цифры.
Стенд нужен на всех следующих этапах, поэтому сделай его аккуратно.

1. Каталог `scripts/eval/`. Команда: `node scripts/eval/run.mjs --scenario <имя> [--provider fake|live] [--budget-usd N]`.
   По умолчанию `fake`; `live` в этом этапе не запускать, только подготовить флаг и проверку бюджета.
2. Кампания создаётся с нуля через существующую подготовку мира и кампании, как в
   `tests/universal-bootstrap-fixture.mjs` и `tests/astra-freedom-fixture.mjs` (`takenOver`),
   на одноразовой PGlite-базе с миграциями. Никакой ручной подстановки строк в базу между ходами.
3. Сценарий — файл в `scripts/eval/scenarios/*.json`: список ходов игрока и ожидаемых проверок состояния
   после хода (например: «существует NPC с именем, похожим на "мельник"», «у героя на 5 монет меньше»,
   «в инвентаре есть предмет "хлеб"», «задание в статусе complete», «награда выплачена ровно один раз»).
   Для фейкового провайдера сценарий содержит заранее записанные ответы модели в нынешнем формате Astra.
4. Метрики на каждый ход пиши в `scripts/eval/out/<run>.jsonl`: время хода, число запросов к модели,
   токены (input/output/cached/reasoning, если есть), итог хода (committed/failed/awaiting_confirmation),
   код ошибки, краткая сводка изменений (NPC, места, предметы, задания, деньги), какие проверки сценария прошли.
   Каталог `out/` — в `.gitignore`.
5. Сценарии (по таблице приёмки из плана, начиная с только что созданной кампании):
   1. мельник: разговор → принятая работа → NPC и задание созданы в том же ходу;
   2. то же при присутствии NPC с Character Model;
   3. выполнение и оплата; повтор того же хода и новая фраза «он мне ещё должен» → выплата ровно один раз;
   4. новый пекарь продаёт хлеб; попытка купить без денег → ни списания, ни хлеба;
   5. съесть хлеб, отдать второй спутнику;
   6. сейв → загрузка → возвращение к мельнику через несколько ходов: тот же NPC, нет дубля;
   7. награда 500 монет и трофейный меч;
   8. десять ходов, где игрок выпытывает тайну NPC.
   Для фейкового провайдера пиши ответы так, как их попыталась бы дать модель, честно в текущем формате.
   Ожидаемый результат на нынешней версии: часть сценариев не проходит — это и есть исходная точка.
6. Сводка: `node scripts/eval/report.mjs <run>` печатает таблицу по сценариям и медианы метрик.

## 4. Отчёт об исходной точке

Создай `docs/BASELINE.md`:
- результаты typecheck/lint/test/build;
- результаты 8 сценариев на фейковом провайдере: что прошло, что нет и почему (с файлами и функциями);
- сколько запросов к модели делает текущий путь хода в типичных случаях (по коду и по стенду);
- что нужно, чтобы владелец прогнал живой замер Astra на стенде (команда, ориентировочный бюджет), но не запускай.

## 5. Готово, когда

- ветка `claude/stage-0-baseline` содержит архив документов, стенд, сценарии и `docs/BASELINE.md`;
- игровой код (`src/`) и миграции не изменены;
- typecheck/lint/test/build прогнаны на финальном состоянии ветки, результаты записаны;
- в конце — короткий отчёт владельцу по-русски: что сделано, где смотреть, какие сценарии сейчас падают, что дальше.

Ничего не пушь в `main`. Ветку можно запушить в `origin`, если владелец разрешит.
