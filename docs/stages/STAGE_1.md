# Этап 1 — две модели

Прочитай `CLAUDE.md`, `docs/REBUILD_PLAN.md` (владелец положит обновлённую версию) и `docs/BASELINE.md`.
Ветка: `claude/stage-1-models` от `claude/stage-0-baseline`.

Цель этапа: у приложения есть общий интерфейс модели-ведущего `DmModel` и два адаптера —
Claude Opus 5.5 и GPT-6 Astra — с потоковым текстом, вызовами инструментов, учётом токенов и цены.
Выбор модели хранится в настройках кампании и закрепляется за ходом.
Нынешний ход Astra (один JSON по схеме) **не меняется** и продолжает работать как есть:
новый цикл хода с инструментами — это этап 2. В интерфейс приложения переключатель модели не выводим (этап 5).

## 2. Интерфейс `DmModel`

Новый каталог `src/lib/server/dm/model/`. Один вызов адаптера = один запрос к модели (цикл хода — этап 2).

Вход:
- системная часть из блоков: стабильный префикс (помечен как кэшируемый) и изменчивая часть;
- история сообщений, включая прошлые вызовы инструментов и их результаты (с ID вызова);
- описания инструментов в **нейтральной форме**: имя, описание, JSON Schema, где необязательные поля
  помечены явно;
- effort (`low | medium | high | max` — сопоставить с тем, что есть у каждой модели), лимит вывода, `AbortSignal`.

Выход — поток событий:
- `text_delta`, `tool_call` (id, имя, аргументы как строка JSON), `usage`
  (input, output, cache_read, cache_write, reasoning — что модель отдаёт),
  `stop` (`end | tool_use | max_tokens | refusal | other`);
- ошибки — по классам: `retryable_transport`, `rate_limited`, `provider_rejected`, `not_configured`, `fatal`.
  Повтор допустим только до первого полученного события; после начала потока — ошибка без повтора.

Компилятор схем инструментов: из нейтральной формы делает схему под каждого провайдера
(для OpenAI strict — все поля обязательные, необязательные как `тип | null`; для Anthropic strict —
необязательные поля просто не в `required`) и **при старте** проверяет лимиты провайдера, падая с понятной ошибкой.
Аргументы от модели сервер всё равно проверяет сам — strict-режим помогает, но не заменяет проверку.

Ключи — только на сервере из `.env.local`. Нет ключа — ошибка `not_configured` с понятным текстом, без падения при импорте.
Таблица цен — в одном месте; функция «стоимость по usage».
