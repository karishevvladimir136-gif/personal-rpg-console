# План переделки AI-DM (REBUILD PLAN)

Источник: ревью архитектуры и план от 2026-10-14. Этот файл — рабочая версия плана для Claude Code.
Ветка-основа: `claude/rebuild-base` от `65dc99c` (main `8ad7b87` + общая инструкция fictional freedom).
WIP `338667d` и документ generic contract `22b2e51` — источник идей и кода, а не основа; черновую миграцию из WIP не применять.

## 1. Цель и критерии

В приложении DM ведёт не хуже той же модели в чате, а приложение добавляет честный учёт мира,
память на сотни часов, сейвы, кубики и красивый лист партии. Работает для любого мира и любой кампании.

| Метрика | Цель (уточнить после замера в этапе 0) |
| --- | --- |
| Время до первого слова | ≤ 5 с |
| Полный ход, медиана | ≤ 20 с |
| Ходы, закончившиеся «повторить» | < 2% |
| Приёмка на 30 ходов (новый мир → кампания → мельник → пекарь → сейв → возврат) | проходит без ручных правок БД |
| Слепое сравнение с чатом на 3 одинаковых сценах | приложение не хуже по оценке владельца |

## 2. Ключевые решения

| Было | Станет |
| --- | --- |
| Один большой JSON-ответ со схемой из динамических enum ID | Состояние меняется вызовами инструментов (tools), текст — свободный, стримится |
| Новый NPC/место/задание невозможны без записи заранее (schema enums `npcIds`, `publicSellerIds`, `purchasable`; фильтр контекста по `presentEntityIds`/`routeLocationIds`) | Инструменты создают NPC, места, предметы, задания по ходу игры |
| private-informed: план на high + отдельный рассказчик без мотивов NPC | Один ведущий видит тайны и Character Models, не раскрывает их игроку. Двухэтапный режим — опция кампании |
| `requireRule` роняет весь ход | Отклоняется один вызов, модель получает причину и продолжает |
| Лимиты 1–20 монет/шт., создаются только food/supply/misc | Лимиты в настройках кампании; категории weapon/armor/gear/tool/consumable/misc со свойствами текстом |
| Логика эффектов в TS и повторно в PL/pgSQL (миграция 48) | Логика в TS; SQL атомарно применяет и стережёт инварианты |
| Только Astra, модель зашита в `astra-primary-provider.ts` | Opus 5.5 или Astra на выбор в настройках кампании, закрепляется за ходом |
| Две среды хода (legacy `runTurn` + Astra) и env-флаг `RPG_ASTRA_PRIMARY_P1` | Одна новая среда для новых ходов; старые ходы читаются по своим закреплённым путям |
| Кубики под домашний профиль (урон — один кубик без модификатора) | Бросок любой формулы (`1d20+7`, `2d6`, `1d100`, преимущество/помеха) с причиной; модификатор берётся из листа персонажа и виден в квитанции |
| Новая кампания играет по Astra только после «takeover», мир замораживается | Новая кампания с первой сцены идёт по новому ходу; мир из World Library — стартовые данные кампании |

Не меняется: durable begin с исходным вводом, operation ID, lease, атомарный коммит, exact-once наград,
серверные кубики с квитанциями, сейвы/ветки/fence, Memory, DM Craft, правки владельца выше всего.

## 3. Новый ход

```text
ввод сохранён (durable begin, operation ID, timeline fence)
  → контекст: состояние кампании, канон и правки, недавние сцены, память,
    DM Craft + DM Style + Afterglow, Character Models упомянутых/присутствующих NPC
  → модель-ведущий (Opus 5.5 или Astra) в цикле с инструментами:
      вызов инструмента → сервер проверяет против ТЕНЕВОГО состояния хода
      → квитанция (принят + результат | отклонён + причина) → модель продолжает
  → модель пишет текст, он стримится игроку
  → атомарный коммит: сцена + все принятые изменения + приватные патчи
  → после коммита: обслуживание памяти в фоне
```

- Каждая квитанция сохраняется в checkpoint хода сразу (как `recordAstraTool` сейчас).
  Повтор после сбоя переигрывает разговор с моделью, подставляя сохранённые квитанции, и не бросает кубики заново.
- Интерактивные кубики: если бросок показываемый и включены интерактивные кубики/переброс —
  ход встаёт на паузу `awaiting_confirmation`, как сейчас; Continue продолжает разговор с той же квитанцией.
- Модель, тайминг и режим приватности закрепляются за операцией (pin) при begin.
- Текст хранится как сцена; изменения — как набор RecordChange, собранный из теневого состояния.

### Инструменты (черновой набор, ≤ 20 строгих инструментов)

| Инструмент | Что делает | Проверки сервера |
| --- | --- | --- |
| `roll` | формула кубиков, причина, кто бросает, видимость, КС (опц.), модификатор из поля листа (опц.) | формула разбирается сервером; модификатор берётся из листа, если указан источник |
| `query_state` | точные значения: хиты, ресурсы, инвентарь, деньги, место | только кампания и ветка хода |
| `upsert_character` | создать/обновить NPC: имя, описание, присутствие, при желании статблок текстом | не перезаписывать чужую запись; не трогать героя игрока без правила |
| `upsert_place` | создать/обновить локацию, отметить известной/посещённой | — |
| `move_party` | переход в локацию с затратой времени | время > 0 при смене локации |
| `item` | create / transfer / consume / equip / unequip / split | владение, количество ≥ 0, слоты, сохранение количества при передаче |
| `money` | transfer между персонажами / grant (обоснование) / spend | баланс ≥ 0; grant ограничен лимитом кампании |
| `resource` | изменить именованный счётчик: хиты, ячейки, стресс, рассудок… | границы 0..max; урон по хитам — по квитанции `roll` или явному правилу |
| `quest` | create / update / complete / fail / claim_reward | одна выплата награды; claim по сохранённым условиям |
| `advance_time` | минуты, причина | ≥ 0, ≤ лимита на ход |
| `rest` | короткий/долгий отдых через существующие правила отдыха | существующие хелперы rest/provisions |
| `note_character` | обновление Character Model NPC (убеждения, отношения, текущее состояние, эпизоды) | существующие валидаторы Character Model; ядро личности менять нельзя |
| `note_world` | приватные факты, часы, последствия (как private patches сейчас) | существующие валидаторы private patches |
| `combat` | начать/закончить столкновение, позиции | существующие combat-хелперы, где применимы |

Ссылки на записи — по ID из контекста или по локальному ключу записи, созданной ранее в этом же ходе.
При создании NPC с именем, совпадающим с известным, сервер возвращает подсказку с существующим ID; решает модель.

## 4. Две модели

Общий интерфейс `DmModel`: поток текста, вызовы инструментов, расход токенов (input/output/cached/thinking).

- **Claude Opus 5.5** (`claude-opus-5-5`): Messages API, strict tools, стриминг, prompt caching
  (стабильный префикс: инструкции, доктрина, Craft, мир — с cache_control). Effort по умолчанию medium,
  сравнить с high на стенде. Цена: $4 вход / $20 выход за 1M токенов, чтение кэша — 5% цены входа.
  Ограничения схем у Claude: нет minLength/maxLength/minimum/maximum, maxItems > 1, не больше 16 параметров
  с anyOf/type-массивами — проверки длины/границ делаем на сервере.
  Документация: https://platform.claude.com/docs/en/build-with-claude/structured-outputs.md,
  https://platform.claude.com/docs/en/build-with-claude/prompt-caching.md,
  https://platform.claude.com/docs/en/build-with-claude/effort.md
- **GPT-6 Astra** (`gpt-6-astra`): существующий транспорт Responses API, перевести на function tools и стриминг.
  Поддержку проверить по актуальной документации OpenAI в начале этапа 1.

Выбор модели и глубины — в настройках кампании (`runtimePolicy`), `providerId` расширить до `anthropic`.

## 5. Наработки, которые сохраняем

DM Craft (Core Doctrine + карточки, версии), DM Style (7 настроек), Chat with DM, Character Models
(теперь видны ведущему полностью; до 4 персонажей в сцене), Cognitive Craft (`cognitive-world`),
Positive Afterglow (тон и сила трагедии), RPG Design Doctrine (сжать в «как вести»), Memory,
синтетические сцены Mega DM (`test-fixtures/mega-dm`) — стенд для слепого сравнения моделей.

## 6. Этапы

0. **Подготовка и замер.** CLAUDE.md, архив старых отчётов, стенд оценки (сценарии + метрики), исходные цифры.
1. **Две модели.** `DmModel`, адаптеры Anthropic и OpenAI, выбор в настройках кампании.
2. **Новый цикл хода.** Инструменты, теневое состояние, отказ одного вызова, стриминг, пауза кубиков, повтор.
3. **Запись.** Миграция 52: атомарная запись изменений хода с инвариантами; лимиты кампании; совместимость старых ходов и сейвов.
4. **Контекст и промпт.** «Как вести» из доктрины/Craft/Afterglow; полные Character Models; упомянутые NPC; стабильный кэшируемый префикс.
5. **Интерфейс.** Стриминг; лист партии в духе `design/registry-reference.html`; переключатель модели; «что изменилось» после хода.
6. **Выпуск.** Бэкап, миграция на базе владельца, 30 ходов живой игры, заморозка старой среды, уборка мёртвого кода.

Следующий этап начинается только после проверки предыдущего и слова владельца «дальше».

## 7. Риски

- Существующие кампании (Iris): старые ходы — на старых путях; новые ходы читают данные World Takeover. Проверять на копии базы.
- Утечка тайн одним ведущим: журнал литеральной проверки, 10 провокационных ходов в приёмке, двухэтапный режим как опция.
- Цена Opus при многих инструментах: замер на этапе 1, лимит на ход.
- После выпуска: перенос кампании «Мир Шва» как пакета мира.
