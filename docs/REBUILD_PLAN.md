# План переделки AI-DM (REBUILD PLAN)

Источник: ревью архитектуры и план от 2026-10-14. Этот файл — рабочая версия плана для Claude Code.
Ветка-основа: `claude/rebuild-base` от `65dc99c` (main `8ad7b87` + общая инструкция fictional freedom).
WIP `338667d` и документ generic contract `22b2e51` — источник идей и кода, а не основа; черновую миграцию из WIP не применять.

## 1. Цель и критерии

В приложении DM ведёт не хуже той же модели в чате, а приложение добавляет честный учёт мира,
память на сотни часов, сейвы, кубики и красивый лист партии. Работает для любого мира и любой кампании.

| Метрика | Цель (уточнить после замера в этапе 0) |
| --- | --- |
| Время до первого слова | ≤ 5 с |
| Полный ход, медиана | ≤ 20 с |
| Ходы, закончившиеся «повторить» | < 2% |
| Приёмка на 30 ходов (новый мир → кампания → мельник → пекарь → сейв → возврат) | проходит без ручных правок БД |
| Слепое сравнение с чатом на 3 одинаковых сценах | приложение не хуже по оценке владельца |

## 2. Ключевые решения

| Было | Станет |
| --- | --- |
| Один большой JSON-ответ со схемой из динамических enum ID | Состояние меняется вызовами инструментов (tools), текст — свободный, стримится |
| Новый NPC/место/задание невозможны без записи заранее (schema enums `npcIds`, `publicSellerIds`, `purchasable`; фильтр контекста по `presentEntityIds`/`routeLocationIds`) | Инструменты создают NPC, места, предметы, задания по ходу игры |
| private-informed: план на high + отдельный рассказчик без мотивов NPC | Один ведущий видит тайны и Character Models, не раскрывает их игроку. Двухэтапный режим — опция кампании |
| `requireRule` роняет весь ход | Отклоняется один вызов, модель получает причину и продолжает |
| Лимиты 1–20 монет/шт., создаются только food/supply/misc | Лимиты в настройках кампании; категории weapon/armor/gear/tool/consumable/misc со свойствами текстом |
| Логика эффектов в TS и повторно в PL/pgSQL (миграция 48) | Логика в TS; SQL атомарно применяет и стережёт инварианты |
| Только Astra, модель зашита в `astra-primary-provider.ts` | Opus 5.5 или Astra на выбор в настройках кампании, закрепляется за ходом |
| Две среды хода (legacy `runTurn` + Astra) и env-флаг `RPG_ASTRA_PRIMARY_P1` | Одна новая среда для новых ходов; старые ходы читаются по своим закреплённым путям |
| Кубики под домашний профиль (урон — один кубик без модификатора) | Бросок любой формулы (`1d20+7`, `2d6`, `1d100`, преимущество/помеха) с причиной; модификатор берётся из листа персонажа и виден в квитанции |
| Новая кампания играет по Astra только после «takeover», мир замораживается | Новая кампания с первой сцены идёт по новому ходу; мир из World Library — стартовые данные кампании |

Не меняется: durable begin с исходным вводом, operation ID, lease, атомарный коммит, exact-once наград,
серверные кубики с квитанциями, сейвы/ветки/fence, Memory, DM Craft, правки владельца выше всего.

## 3. Новый ход

```text
ввод сохранён (durable begin, operation ID, timeline fence)
  → контекст: состояние кампании, канон и правки, недавние сцены, память,
    DM Craft + DM Style + Afterglow, Character Models упомянутых/присутствующих NPC
  → модель-ведущий (Opus 5.5 или Astra) в цикле с инструментами:
      вызов инструмента → сервер проверяет против ТЕНЕВОГО состояния хода
      → квитанция (принят + результат | отклонён + причина) → модель продолжает
  → модель пишет текст, он стримится игроку
  → атомарный коммит: сцена + все принятые изменения + приватные патчи
  → после коммита: обслуживание памяти в фоне
```

- Каждая квитанция сохраняется в checkpoint хода сразу (как `recordAstraTool` сейчас).
  Повтор после сбоя переигрывает разговор с моделью, подставляя сохранённые квитанции, и не бросает кубики заново.
- Интерактивные кубики: если бросок показываемый и включены интерактивные кубики/переброс —
  ход встаёт на паузу `awaiting_confirmation`, как сейчас; Continue продолжает разговор с той же квитанцией.
- Модель, тайминг и режим приватности закрепляются за операцией (pin) при begin.
- Текст хранится как сцена; изменения — как набор RecordChange, собранный из теневого состояния.

### Инструменты (черновой набор, ≤ 20 строгих инструментов)

| Инструмент | Что делает | Проверки сервера |
| --- | --- | --- |
| `roll` | формула кубиков, причина, кто бросает, видимость, КС (опц.), модификатор из поля листа (опц.) | формула разбирается сервером; модификатор берётся из листа, если указан источник |
| `query_state` | точные значения: хиты, ресурсы, инвентарь, деньги, место | только кампания и ветка хода |
| `upsert_character` | создать/обновить NPC: имя, описание, присутствие, при желании статблок текстом | не перезаписывать чужую запись; не трогать героя игрока без правила |
| `upsert_place` | создать/обновить локацию, отметить известной/посещённой | — |
| `move_party` | переход в локацию с затратой времени | время > 0 при смене локации |
| `item` | create / transfer / consume / equip / unequip / split | владение, количество ≥ 0, слоты, сохранение количества при передаче |
| `money` | transfer между персонажами / grant (обоснование) / spend | баланс ≥ 0; grant ограничен лимитом кампании |
| `resource` | изменить именованный счётчик: хиты, ячейки, стресс, рассудок… | границы 0..max; урон по хитам — по квитанции `roll` или явному правилу |
| `quest` | create / update / complete / fail / claim_reward | одна выплата награды; claim по сохранённым условиям |
| `advance_time` | минуты, причина | ≥ 0, ≤ лимита на ход |
| `rest` | короткий/долгий отдых через существующие правила отдыха | существующие хелперы rest/provisions |
| `note_character` | обновление Character Model NPC (убеждения, отношения, текущее состояние, эпизоды) | существующие валидаторы Character Model; ядро личности менять нельзя |
| `note_world` | приватные факты, часы, последствия (как private patches сейчас) | существующие валидаторы private patches |
| `combat` | начать/закончить столкновение, позиции | существующие combat-хелперы, где применимы |

Ссылки на записи — по ID из контекста или по локальному ключу записи, созданной ранее в этом же ходе.
При создании NPC с именем, совпадающим с известным, сервер возвращает подсказку с существующим ID; решает модель.

## 4. Две модели

Общий интерфейс `DmModel`: поток текста, вызовы инструментов, расход токенов (input/output/cached/thinking).

- **Claude Opus 5.5** (`claude-opus-5-5`): Messages API, strict tools, стриминг, prompt caching
  (стабильный префикс: инструкции, доктрина, Craft, мир — с cache_control). Effort по умолчанию medium,
  сравнить с high на стенде. Цена: $4 вход / $20 выход за 1M токенов, чтение кэша — 5% цены входа.
  Ограничения схем у Claude: нет minLength/maxLength/minimum/maximum, maxItems > 1, не больше 16 параметров
  с anyOf/type-массивами — проверки длины/границ делаем на сервере.
  Документация: https://platform.claude.com/docs/en/build-with-claude/structured-outputs.md,
  https://platform.claude.com/docs/en/build-with-claude/prompt-caching.md,
  https://platform.claude.com/docs/en/build-with-claude/effort.md
- **GPT-6 Astra** (`gpt-6-astra`): существующий транспорт Responses API, перевести на function tools и стриминг.
  Поддержку проверить по актуальной документации OpenAI в начале этапа 1.

Выбор модели и глубины — в настройках кампании (`runtimePolicy`), `providerId` расширить до `anthropic`.

## 8. Интерфейс и картинки (для этапа 5, решения уже приняты)

Макет: дизайн-холст «RPG Console — новый интерфейс» (экраны: игра, телефон, персонаж, имущество, карта, журнал,
кодекс, партия, настройки). Стиль — `design/registry-reference.html`: тёмная кожа, латунь, пергамент.

- **Журнал и Кодекс** — как в реестре: главная арка с шагами, задания, открытые нити, долги и обещания, выполненное;
  кодекс по отношениям (семья, союзники, мутные, враги) и фракции, поиск. Только то, что знает герой.
- **Партия**: отряд и резерв, на карточке «К тебе» — только то, что герой мог заметить.
  Кнопка «Поговорить» (в любой момент, кроме боя) и «Совет партии» (отвечают все присутствующие).
  Технически это обычный ход: ввод с адресатом, тот же ведущий, тот же набор инструментов, идёт игровое время,
  спутник запоминает разговор (Character Model). В бою кнопки недоступны.
- **Имущество / Лагерь**: транспорт, базы, вьючные и ездовые — это записи, которые ведущий создаёт и убирает
  по ходу истории; у каждой своё хранилище (на основе существующих storage kinds: player/companion/camp/transport/merchant).
  Лагерь (общий запас) есть всегда. Пока нет ничего, кроме лагеря, раздел в меню называется «Лагерь»;
  появился транспорт или база — «Имущество». У корабля полная страница: картинка, характеристики, вооружение, трюм, пассажиры.
  Скорее всего понадобится инструмент `holding` (create/update/remove) — уложиться в лимит инструментов.
- **Карта**: из нынешнего `atlas-map.tsx` — уровни мир/регион/местность, фон-иллюстрация, метки из записей,
  иллюстрация места, «Наметить курс» с готовым текстом для хода, ручная расстановка меток, места без метки.
  Добавить: линия маршрута, статусы «цель» и «слухи».
- **Настройки**: модель-ведущий (Opus 5.5 / Astra) и глубина; один ведущий или два этапа; правило бросков
  («все я» / «важные я, остальное ведущий» / «все ведущий»); книги правил как знания; лимиты кампании;
  сводка последних ходов (время до первого слова, цена хода, отклонённые действия).
- **Автокартинки fal**: после коммита хода, в фоне, ход никогда не ждёт картинку.
  Новый предмет в инвентаре → картинка сразу (одинаковые предметы делят одну); портреты — спутникам и важным NPC
  при первой встрече, прохожим по кнопке; иллюстрации новых мест и ключевых сцен; транспорт и базы при появлении.
  «Перерисовать» везде: старая версия видна, пока новая не готова, прошлые версии можно вернуть.
  Общий стиль — визуальная библия мира. Дневной лимит картинок в настройках. Ячейка без картинки мерцает «рисуется».

## 8б. Глубина размышлений (решение владельца)

Владелец в чате играет на уровне «на деление ниже максимума»: Astra extra high, Opus 5.5 high или extra high — «и умно, и быстро».
Уровни глубины в приложении — из возможностей модели (не жёстко 4 кнопки): обычно low / medium / high / extra high / max.
В этапе 4 сравнить по качеству и скорости: Opus high и extra high, Astra high и extra high (плюс medium как быстрый вариант),
на одних и тех же сценах, вслепую для владельца. Значения по умолчанию выбрать по его оценке и цифрам стенда.
С этапа 2б глубина задаётся по раундам: первый запрос хода — на уровне кампании, продолжения после инструментов — ниже.

**Авто-глубина по напряжённости сцены (этап 4).** Одна модель на всю кампанию (голос ведущего и кэш не должны
скакать), но глубина меняется по сцене в пределах диапазона владельца (например, «от high до max»):
- сигналы сервера: активный бой, кульминация арки, допрос/выпытывание тайны, много важных NPC в сцене, ставки (смерть, большая сделка);
- подсказка ведущего: в `finish_turn` модель отмечает, насколько напряжённым будет следующий ход (она знает, что назревает);
- простые сцены (таверна, дорога, покупки) — нижняя граница диапазона, напряжённые — верхняя.
Проверить на стенде: экономия времени/денег на простых сценах без потери качества на напряжённых; учесть, как смена глубины
влияет на кэш у каждого провайдера. По документации Anthropic смена `output_config.effort` сбрасывает кэш сообщений
(а на части моделей и tools/system), **но** на моделях с поддержкой effort внутри сообщений смена, переданная сообщением
`role: "system"` в `messages`, сохраняет кэшированный префикс — проверить поддержку у Opus 5.5 и использовать её.
У OpenAI — `configuration_update` (найдено в этапе 2б), префикс сохраняется. Гистерезис: менять глубину только при смене
класса напряжённости, а не каждый ход.
**Младшие модели — только для фоновой работы**, где не нужен голос ведущего: сжатие памяти, служебные сводки, промпты для
картинок, черновики записей кодекса. Ведущий, подготовка между сессиями и «Ранее в…» — всегда основная модель.

## 9. Живые персонажи и мир за кадром (для этапа 4, решение владельца)

Принцип: Opus и Astra — сильные модели. Приложение не мешает им импровизировать, а даёт всё нужное.
Ограничения — только защита данных и разумный бюджет контекста, а не «экономия на модели».

- **Без тесноты.** Убрать `MAX_ACTORS = 2` и жёсткие 120 символов на поле. В контекст идут Character Models
  всех присутствующих и упомянутых важных NPC, плюс их ближайшие связи по графу отношений — пока укладываемся
  в бюджет контекста (лимит по токенам, а не по числу персонажей). Пределы полей — только как защита от мусора
  (порядка сотен–тысяч символов, списки щедрее). Ядро личности по-прежнему не переписывается случайно.
- **Новые важные NPC получают модель на ходу.** Ведущий может завести Character Model для нового персонажа
  в том же ходе, где он появился (через `upsert_character` / `note_character`), без ручной подготовки.
- **Жизнь за кадром.** Когда в ходе проходит заметное время (отдых, путешествие, пропуск дней), ведущий
  продвигает планы важных NPC и фракций: часы, последствия, изменения отношений — через существующие часы
  и последствия мира (`note_world`) и `note_character`. Не новый агент и не фоновый процесс, а часть того же хода.
  Игрок видит только то, что дошло до героя (слухи, письма, последствия); остальное — приватно у ведущего.
- **Проверка на стенде.** Сценарий: NPC затаил обиду → партия три дня в пути → по возвращении видны последствия
  его действий, согласованные с его моделью. Плюс прежние 20 проб Living Characters на синтетических сценах Mega DM.

## 10. Долгая кампания: чтобы на сотом часу было интереснее, чем на втором (решение владельца)

Уже есть в доктрине (§36 «Long-Form Campaign Craft», Cognitive Craft, Positive Afterglow) и сохраняется:
Return With Delta, волны вместо постоянной эскалации, посадка → дремота → отдача, последствия на разных горизонтах,
домашняя база, отношения как двигатель сюжета, тишина после пика. Ниже — то, что добавляем.

- **Весь крафт — в кэш (этап 4).** Сейчас в этап хода попадают максимум 2 карточки DM Craft. Новое правило:
  вся одобренная доктрина (сжатая до чёткого «как вести») и весь «долгий крафт» лежат в стабильном кэшируемом префиксе;
  выбор карточек по релевантности — только когда библиотека реально не помещается.
  Порядок слоёв запроса (от постоянного к свежему, точка кэша на границе каждого):
  1) как вести: доктрина, крафт, DM Style, Afterglow; 2) мир: библия мира, правила как знания, канон;
  3) живое: Character Models, нити, долги, блокнот подготовки; 4) сейчас: недавние сцены, состояние, ввод игрока.
  Ничего изменчивого не класть в ранние слои. Стенд считает долю чтения из кэша и цену хода.
- **1. Подготовка между сессиями (этап 4).** При закрытии сессии отдельный вызов ведущего (высокая глубина)
  «переваривает» сессию: двигает планы NPC и фракций за кадром (раздел 9), отмечает, что зацепило игрока,
  готовит 2–3 ситуации (не сюжета) на следующий раз, отмечает созревшие посаженные семена. Результат — приватные
  заметки ведущего (`note_world` / `note_character`), игрок видит только последствия. Один вызов на сессию.
  Запуск: кнопка «Закончить сессию»; если сессию не закрыли — при следующем входе, до «Ранее в…». Работает в фоне,
  игру не задерживает. Мир за кадром двигается только на прошедшее в сессии игровое время (реальное отсутствие
  владельца мир не двигает — правило Positive Afterglow). Ситуации — заготовки, не рельсы. Блокнот привязан к линии
  времени (у загруженного сейва — свой). По умолчанию скрыт; опция «заглянуть в блокнот мастера».
- **2. «Ранее в …» и хроника-книга (этап 5).** При входе в игру — короткий пересказ прошлой сессии голосом ведущего.
  Сессии получают названия глав. Хроника — читаемая книга кампании с иллюстрациями fal.
- **3. «Как ты хочешь это сделать?» (этапы 2 и 5).** На решающем ударе или кульминации ведущий может отдать
  описание игроку: ход заканчивается приглашением, следующий ввод игрока становится каноном момента (в пределах
  уже принятого результата броска). В интерфейсе — заметная плашка «Твой момент».
- **4. Учёт внимания (этап 4).** Ведущий видит, чьи истории давно не звучали (спутники, их личные нити, долги,
  обещания) — по числу сессий с последнего касания. У каждого спутника — личная арка с вехами, открываемыми по доверию.
- **5. Счётчик разнообразия (этап 4).** По последним сценам — какие типы были (бой, разговор, тайна, исследование,
  тихая сцена, юмор, торговля, путешествие) и чего давно не было. Тип сцены ведущий отмечает сам при записи хода.
  Это подсказка, не квота.
- **6. Злодеи и тема (этап 4, тонко).** Злодеи не «зло ради зла»: у каждого — понятная мотивация, ресурсы,
  методы и план, который движется за кадром. «Понятный» не значит «серый» и не значит «сочувственный»:
  допустимы идейные противники, прагматики и простые эгоманьяки, которым нужны власть и деньги — это тоже реально.
  Разнообразие антагонистов важнее единого шаблона. У кампании может быть тема-вопрос; ведущий возвращается к ней
  в разных обличьях, но не морализирует и не вставляет её в каждую сцену.
- **7. Что любит игрок (этап 4).** Короткая записка ведущего «что нравится игроку» (темы, типы сцен, темп боёв),
  **видимая и редактируемая** владельцем в настройках кампании. Это не скрытая оценка настроения
  (её запрещает Positive Afterglow), а то, что мастер спросил бы на нулевой сессии.
- **8. Финал и наследие (после выпуска).** Финал сезона, эпилоги персонажей; следующая кампания в том же мире
  получает наследие прошлой (герои становятся легендами и NPC, мир помнит изменения). Иерархия Мир → Кампания это поддерживает.

Проверка на стенде (этап 4): синтетическая длинная кампания Mega DM + новые пробы — подготовка между сессиями даёт
ситуации из открытых нитей; давно забытый спутник получает сцену; после трёх боёв подряд ведущий предлагает другое;
два злодея с разными мотивами ведут себя по-разному и последовательно.

## 11. Уроки рынка (обзор 2026, для этапа 4)

Обзор: Everweave, AI Realm, Friends & Fables, AI Dungeon, RoleForge, DungeonsDeep, открытый Talemate. Общие беды рынка:
потеря памяти и дрейф на длинных кампаниях, ошибки правил и математики, «ненастоящие» кубики, противоречия состояния
(«существо одновременно живо и мертво»), сползание в Мэри Сью. Коммерческие продукты ограничены ценой хода
(подписка ~10–40 $ в месяц за сотни ходов) и потому используют слабые модели — у нас этого ограничения нет.
У нас уже есть то, чего им не хватает: серверные кубики с квитанциями, состояние через проверяемые инструменты,
модели персонажей, сейвы, топовые модели без экономии на ходе. Что берём:

- **Закреплённое владельцем.** Короткий список фактов, которые всегда в контексте ведущего (как pinned facts в Talemate) —
  владелец закрепляет/открепляет в один клик из журнала, кодекса или сцены. Слой «живое», кэшируется.
- **Поиск в памяти через явные вопросы.** Перед поиском по памяти превращать ход игрока в явные запросы к канону с именами
  участников сцены («что Изольда знает о сердечнике?»), а не искать по сырому тексту хода.
- **Анти-Мэри-Сью.** Явные установки ведущему: мир суверенен, намерение не диктует исход, NPC могут отказать, провал — канон,
  удача не должна быть бесплатной. Плюс метрики на стенде и в длинной синтетической кампании: доля успехов в спорных
  проверках против ожидаемой по кубикам, доля отказов NPC, серии «незаработанных» побед. Исследования показывают, что
  «приятные» роли усиливают поддакивание, а явные установки на честность его снижают.
- **Сопротивление мира, а не симулятор бога** (главная боль владельца в AI Realm: через 2 часа «мега-файрболы по армиям без риска»).
  Опора — доктрина §37–38 (заслуженный рост, честный вызов, уровни угроз), плюс явно для ведущего: планы встречают
  сопротивление, соразмерное ставкам; частичный успех — нормальный исход («бомбу нашли, но не всю»); враги учатся и меняют
  тактику; сила стоит ресурсов, и ресурсы кончаются; у мира есть угрозы сильнее героя. Метрики на стенде и в длинной кампании:
  доля боёв с реально неясным исходом, потерянные хиты и ресурсы за бой, частота «на волоске», сколько боёв выиграно без затрат.
- **Не терять память молча.** Где память выбирается по релевантности, стенд проверяет, что ключевые факты не выпадают
  (сравнение с полным контекстом на синтетической кампании).

- **Из открытого rpg-mcp (MIT/ISC, github.com/Mnehmos/rpg-mcp)** — тот же принцип, что у нас («модель предлагает, движок проверяет»):
  объединённые инструменты с `action` экономят токены описаний (у них ~50K → 6–8K), ошибки с подсказкой исправления,
  жёсткие проверки ресурсов. Проверить, что наши 16 инструментов компактны; проверки вроде «заклинание не известно» —
  только если их даёт набор правил кампании (правила — знание, не код).

## 12. Память «как в чате-кампании» (для этапа 4)

Кампания «Мир Шва» в чате идёт без галлюцинаций за счёт небольшого набора авторитетных документов, которые всегда перед
ведущим: мир, кодекс ведущего, журнал, лист героя, экипаж и отдельный файл тайн ведущего; они обновляются осознанно после
сессий. Повторить это в приложении: **досье кампании**, собранное из записей (мир и канон, партия и листы, кодекс людей
и фракций, журнал — задания, нити, долги, закреплённое владельцем, приватные тайны и блокнот ведущего), всегда в контексте
в кэшируемых слоях 2–3. Поиск по памяти — дополнение для старых подробностей, а не замена досье. Подготовка между сессиями
(§10.1) обновляет досье так же, как в чате это делалось после сессий.
